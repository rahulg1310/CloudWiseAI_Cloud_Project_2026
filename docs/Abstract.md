# Abstract

Micro, Small and Medium Enterprises (MSMEs) increasingly run their workloads on public cloud platforms, but few have a dedicated FinOps team, so overspending is usually discovered only when the monthly invoice arrives. Native billing consoles report what was spent; they neither predict what will be spent nor explain which resources are wasted. CloudWiseAI is an AI-based FinOps framework that converts daily AWS billing data into three decision aids: a three-month cost forecast, detection of abnormal spending, and ranked cost-saving recommendations with estimated monthly savings.

The backend is a FastAPI service with a PostgreSQL database, and a React dashboard presents the results. An optional assistant answers questions from a snapshot of the user's own data. The system is deployed on AWS (Sydney region, ap-southeast-2): Amazon S3 and CloudFront for the frontend, API Gateway as the HTTPS entry point, EC2 for the application and analysis scripts, RDS PostgreSQL for data, IAM for access control, and CloudWatch with SNS for e-mail alerts. The application and analysis were built and tested locally and then deployed on AWS on 19 October 2026 with a one-script server setup (`src/aws/ec2_setup.sh`) and a step-by-step guide (`src/aws/DEPLOYMENT.md`); three live checks passed (website over HTTPS, API health check and an e-mailed test alert).

The methodology uses a synthetic, CUR-style dataset of 15,950 daily records covering 25 resources over 21 months, with eight injected anomaly events. Anomalies are found with a weekday-aware robust z-score, forecasts come from a ridge model compared with seasonal-naive and ridge-XGBoost alternatives under rolling-origin backtesting, and recommendations follow documented rules. On this dataset the detector found all eight events with no false alarms, whereas a rolling 3-sigma baseline raised 57 false-alarm events; ridge reached 0.45% mean monthly MAPE against 2.47% for the baseline; and six recommendations worth about $7,507 per month were generated. Because the data is synthetic, these figures are optimistic and must be re-validated on real invoices. Lambda-based report ingestion and SageMaker training are left as future work.

**Keywords:** AWS, FinOps, cloud cost optimization, cost forecasting, anomaly detection, MSME
